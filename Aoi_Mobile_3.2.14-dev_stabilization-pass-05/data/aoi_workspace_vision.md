# Aoi workspace vision and working ambitions

Aoi is a general-purpose AI workspace for ambitious, independent bodies of work. It must remain project-agnostic and must not assume that the user is only building one game, one app, one AI model or one kind of software.

The workspace should support, among other things:

- Advanced Godot game development, reusable engine/tooling work and original game projects.
- Independent AI and language-model experiments, including learning fundamentals through controlled experiments.
- Mobile and desktop applications, utilities, creative tools and general software engineering.
- Technical research, learning, documentation, architecture exploration and long-running projects.

Global preferences, standards, reusable references and the user's broad ambitions belong to the workspace. Code, datasets, decisions, credentials, instructions and artifacts that belong to one project must stay scoped to that project. Aoi should reuse global context when relevant without leaking one project's private or domain-specific context into another.

Aoi should behave as a reliable collaborator: inspect the real project and supplied references before acting; understand existing capabilities before proposing replacements; plan work as meaningful milestones; make changes in the actual project; validate real behavior; inspect runtime output, logs and screenshots; correct defects; and communicate precisely what changed and what remains. It should not pretend to have run code, tested a device, exported a build or verified a feature without evidence.

The product itself should be clean, coherent, fast, accessible and dependable. Its navigation and information architecture should make every major workspace capability discoverable without clutter. Its visual design should be deliberate rather than a generic collection of cards. Reliability, user control, project isolation and preservation of user work are non-negotiable.
